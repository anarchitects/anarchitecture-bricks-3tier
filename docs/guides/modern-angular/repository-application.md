# Repository application: anarchitecture-bricks-3tier

Reviewed 2026-10-11 against branch `docs/adr-modern-angular-22`, starting commit `b7fb11d9bf8d363077e875ebfeeb9cff707ab31f`. This inventory complements the [common guide](README.md); it does not replace reading every ADR in full. Re-enumerate ADRs when the branch changes.

## Actual baseline and scope

Angular runtime 22.1.8; CLI/build 22.1.9; NgRx ^22.0.0; Nx 23.2.1; TypeScript 6.0.3; Yarn 4.18.0.

Preserve capability-first libraries, Angular ui/feature/state/data-access layers, explicit state providers and framework-neutral shared TS. Common is technical foundation, not shared business logic. Forms owns configurable intake; it must not replace typed domain APIs or absorb workflow logic.

Preserve Tailwind v4 CSS foundation, accepted foundation/forms/auth sequencing, verified legacy Angular 21 support where promised, and package retirement only after consumers migrate. Current root Angular 22 does not cancel historical release obligations. Keep Better Auth behind session-first facades with internal TypeORM; keep Nest runtime and tooling support separate. No release, deprecation or unpublish is performed here.

## Application gates

Apply A01–A12 only to the relevant Angular implementation/consumer scope. The [traceability matrix](traceability.md) covers the source chapters independently of whether this repository currently implements a topic. “Not currently applicable” is a scope decision, not permission to skip reading local ADRs.

Before implementation, inspect package-level peers and exports, applicable agent instructions, existing tests and resolved build targets. Before a release, validate the consumer and documented support range; a root dependency alone does not establish every package's compatibility. This change modifies documentation and agent instructions only. No runtime manifest, lockfile, public package API or release artifact is changed.

Read the existing [Angular 22, Signal Forms and Tailwind migration guide](../angular-22-signal-forms-tailwind-migration.md) together with the accepted release ADRs. Preserve newsletter UI-only Forms integration, scalar cross-domain references and the repository prohibition on apps/ additions.
